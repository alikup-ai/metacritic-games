# Metacritic Games

Сервис ежечасного сбора данных об играх с Metacritic с разбором отзывов языковой моделью
и веб-интерфейсом.

## Что делает

Каждый час служба берёт **20 игр, ещё не обработанных в текущие сутки**, и проводит их
через конвейер: данные игры → отзывы критиков и пользователей → разбор отзывов моделью.
Результат виден в веб-интерфейсе.

**Возможности:**

- каталог игр с поиском по названию, фильтром по платформам и сортировкой
  (оценка критиков, оценка игроков, дата выхода, название);
- карточка игры: обложка, описание, разработчик, издатель, дата выхода, ссылка на видео,
  оценки по каждой платформе;
- **раздельный** разбор отзывов критиков и игроков: что понравилось, что не понравилось,
  основные темы;
- честное раскрытие полноты анализа — «Проанализировано 200 из 6 595 отзывов (3,0%)»;
- похожие игры: до пяти, с объяснением сходства («тот же жанр», «те же платформы»);
- разбор видеообзоров с YouTube — необязательная часть, требует ключей
  (см. [Видеообзоры](#видеообзоры));
- экран мониторинга `/monitoring`: состояние обработчика, история запусков,
  стадии обработки и ручной запуск.

## Архитектура

Модульный монолит с разделением слоёв, а не микросервисы: масштаб задачи не оправдывает
распределённую систему.

```
Браузер → Next.js → HTTP API → Application → Domain → PostgreSQL
                                    ↑
                        Metacritic, OpenRouter (через порты)
```

```
src/
├─ api/                    HTTP: маршруты, DTO, валидация, ошибки
├─ modules/
│  ├─ catalog/             игры и платформы
│  ├─ ingestion/           обход источника, заявки, конвейер
│  ├─ reviews/             отзывы и снимки
│  ├─ analysis/            разбор отзывов моделью
│  └─ monitoring/          запуски
├─ shared/                 конфигурация, БД, логирование, HTTP
└─ app/                    точка входа и сборка зависимостей
web/                       Next.js
```

Каждый модуль разделён на `domain` (чистая логика), `application` (сценарии) и
`infrastructure` (адаптеры). Правила проверяются сборкой: `npm run lint:boundaries`
падает, если `domain` обратится к базе или `api` — к PostgreSQL напрямую.

Внешние сервисы подключены через порты. Смена шлюза LLM затронула один файл в
`infrastructure` и не коснулась ни домена, ни сценариев.

Подробности — [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md).

## Ежедневная обработка

```
Планировщик (раз в час)
   ↓
RunDailyProcessing ──► заявки на 20 игр
   ↓
ProcessGamePipeline (на каждую игру)
   ↓
fetchGame → fetchReviews → summarize
```

**Реестр заявок — источник истины.** «20 игр в сутки» означает 20 уникальных заявок,
а не 20 успешных обработок: заявка сохраняется даже при сбое, и повторная попытка не
создаёт вторую. Блокировка запуска защищает от лишней параллельной работы, но
идемпотентность обеспечивает именно реестр.

**Первый запуск суток** идёт по разделу New Releases, последующие — по Browse/All-Time/New.

**Стадии независимы.** Сбой одной не выдаёт игру за полностью обработанную:

| Ситуация | Итог |
|---|---|
| Всё удалось | `success` |
| Сбой получения данных игры | `failed`, отзывы и разбор пропущены |
| Отзывы не получены | `failed`, разбор не запускается |
| Снимок отзывов неполон | `partial` |
| Сбой разбора | `partial` — игра и отзывы сохранены |
| Разбор выключен | `partial`, причина `llm_disabled` |

Сбой одной игры не останавливает остальные девятнадцать. Прерванная работа
восстанавливается по истечении аренды заявки.

Подробности — [`docs/WORKERS.md`](docs/WORKERS.md).

## Разбор отзывов

Провайдер — **OpenRouter**; модель задаётся настройкой (`LLM_MODEL`, по умолчанию
`anthropic/claude-haiku-4.5`) и в коде не зашита.

**По умолчанию разбор выключен** (`LLM_ENABLED=false`) — включение начинает тратить
деньги. Чтобы включить, задайте в локальном `.env`:

```
LLM_ENABLED=true
LLM_API_KEY=<ключ OpenRouter>
LLM_MODEL=anthropic/claude-haiku-4.5
```

Проверить на одной игре, не запуская весь конвейер:

```bash
set -a && . ./.env && set +a
node --import tsx scripts/llm-smoke.ts <gameId> user
```

Ключевые решения:

- **Критики и игроки анализируются раздельно** — это разные аудитории и разные шкалы
  (0–100 против 0–10). Их выводы никогда не сводятся в один текст.
- **Детерминированная выборка.** При тысячах отзывов берётся выборка с гарантированной
  долей каждой тональности: при перекосе «131 десятка из 200» негативные мнения
  не теряются. Случайности нет — повторный запуск даёт тот же набор.
- **Ссылки на свидетельства.** Каждый вывод ссылается на конкретные отзывы; ссылка на
  несуществующий отзыв означает отклонение всего ответа.
- **Полнота честно раскрывается.** `analyzedCount`, `totalAvailable`, `coverage` и
  `snapshotCompleteness` вычисляются нашим кодом, а не моделью, и показываются
  пользователю. Выводы по выборке не подаются как мнение всех игроков.
- **Идемпотентность.** Совпадение входного хеша означает пропуск без обращения к модели.
- **Тексты отзывов — недоверенные данные:** передаются как JSON-поля, а не как инструкции.

Подробности — [`docs/AI_PIPELINE.md`](docs/AI_PIPELINE.md).

## Видеообзоры

Необязательная часть задания: к карточке игры добавляется разбор видеообзора с YouTube.
Это **внешние интеграции**, поэтому функция выключена по умолчанию и требует двух ключей.

```
YOUTUBE_ENABLED=true
YOUTUBE_API_KEY=<ключ YouTube Data API v3>
SUPADATA_API_KEY=<ключ Supadata>
```

- **YouTube Data API v3** — поиск ролика и его метаданные (канал, просмотры, длительность).
- **Supadata** — расшифровка речи. Нужна потому, что открытая точка `timedtext` перестала
  отдавать данные, а официальный `captions.download` требует OAuth с правами владельца
  ролика и для чужих видео недоступен. Обход ограничений YouTube не применяется:
  ни `yt-dlp`, ни cookies, ни автоматизация браузера.

Без флага или без ключа функция **молча отключается**: карточка игры и весь конвейер
работают как обычно (ADR-0005). Ключи читаются только из окружения, в клиентский код
и в журнал не попадают.

Запуск разбора для одной игры:

```bash
curl -X POST http://localhost:3001/api/games/<gameId>/video -H "X-Admin-Token: <ваш токен>"
```

Повторный вызов при том же ролике и той же расшифровке возвращает `unchanged`
и к модели не обращается.

Подробности — [`docs/adr/0005-youtube-optional-feature.md`](docs/adr/0005-youtube-optional-feature.md).

## Технологии

| Слой | Выбор |
|---|---|
| Среда | Node.js ≥ 22, TypeScript 5 (strict) |
| База | PostgreSQL 16 |
| Backend | без фреймворка: `node:http` + свой маршрутизатор |
| Разбор HTML | cheerio |
| Валидация | zod |
| Frontend | Next.js 15, React 19 |
| Тесты | Vitest, Playwright |
| Развёртывание | Docker Compose |

Metacritic отдаёт готовый HTML, поэтому headless-браузер не нужен. Для отзывов
используется найденный JSON-эндпоинт — это устраняет зависимость от CSS-селекторов.

## Локальный запуск

```bash
# 1. База
docker compose up -d postgres

# 2. Настройки
cp .env.example .env      # заполнить DATABASE_URL

# 3. Зависимости и схема
npm install
npm run migrate

# 4. Backend (порт 3001)
npm run start:api

# 5. Frontend (порт 3000)
cd web && npm install
API_BASE_URL=http://127.0.0.1:3001 npm run dev
```

> **Порт 3001 занимается одним процессом.** Если запустить второй, он завершится
> с `EADDRINUSE`, а отвечать продолжит старый — и проверка покажет поведение
> прежней версии кода. При ручных проверках останавливайте предыдущий процесс
> или следите за строкой `HTTP-сервер запущен` в его выводе. Автоматические
> проверки этой ловушке не подвержены: E2E поднимает свои экземпляры заново
> (`reuseExistingServer: false`), а Docker Compose пересобирает образы.

Разбор отзывов выключен по умолчанию. Чтобы включить, задайте в `.env`:

```
LLM_ENABLED=true
LLM_API_KEY=<ключ OpenRouter>
```

## Docker Compose

```bash
docker compose up
```

Поднимаются четыре службы:

| Служба | Роль | Порт |
|---|---|---|
| `postgres` | база данных | 5432 |
| `api` | HTTP, обработку не ведёт | 3001 |
| `worker` | обработка по расписанию | — |
| `web` | веб-интерфейс | 3000 |

`api` и `worker` собираются из одного образа и различаются переменной `APP_ROLE`.

Браузер обращается только к `web`; адрес API и секреты в клиентский код не попадают.
Секретов в `docker-compose.yml` нет — значения берутся из окружения либо `.env`.

Ручной запуск обработки:

```bash
curl -X POST http://localhost:3001/api/runs -H "X-Admin-Token: <ваш токен>"
```

## Тесты

| Вид | Количество |
|---|---|
| Backend (модульные и интеграционные) | **832** |
| E2E (desktop + mobile) | **118** |
| **Всего** | **950** |

```bash
npm test                  # backend; интеграционные — на реальной PostgreSQL
cd web && npm run e2e     # E2E
```

Интеграционные тесты работают с настоящей базой: проверяются ограничения целостности и
гонки, а не их имитация. При полном параллельном прогоне один-два E2E-теста
могут оказаться неустойчивыми из-за таймингов (падает каждый раз другой): по отдельности
и на живом стенде они проходят. К Metacritic и OpenRouter тесты не обращаются — источники
подменены. Отдельная команда `npm run test:metacritic-live` обращается к реальному
источнику и в обычный прогон не входит.

## Как проект разрабатывался

Проект выполнен с помощью Claude Code по фазам: исследование → проектирование →
реализация → аудит. После каждой фазы работа останавливалась для проверки.

Принятый порядок:

- **Сначала исследование, потом код.** Контракты Metacritic и OpenRouter проверялись
  живыми запросами, а не восстанавливались по памяти. Так был найден недокументированный
  JSON-эндпоинт отзывов и подтверждено, что платформа передаётся сегментом пути.
- **Каждое существенное решение — в ADR** (13 записей в [`docs/ADR/`](docs/ADR/)).
- **Расхождения фиксируются, а не сглаживаются.** Когда требование противоречило схеме,
  работа останавливалась и расхождение выносилось на решение.
- **Полные логи переписки прилагаются:** [`logs/ai/raw/`](logs/ai/raw/) — сырой JSONL без
  единого изменения, [`logs/ai/merged/`](logs/ai/merged/) — тот же материал, приведённый к
  единому виду (`agent`, `role`, `timestamp`, `eventType`).

## Известные ограничения

Осознанные, а не недоделки:

| Ограничение | Причина |
|---|---|
| Похожие игры не рассчитываются для игр с редким жанром | Совпадений с каталогом нет; выдуманные рекомендации хуже честной пустоты |
| Разбор видео требует ключей YouTube и Supadata | Необязательная часть задания; без ключей функция молча отключается |
| Разбор ведётся по платформе `default` | Отзывы синхронизируются без разбивки по платформам |
| Изменение только текста отзыва не вызывает повторный разбор | Отпечаток снимка считается по ключу и оценке — осознанная экономия |
| Модель получает название игры из slug | Избавляет от лишнего обращения к каталогу |
| Ограничение частоты API хранится в памяти процесса | Достаточно для одного стенда |
| Страница «игра не найдена» отдаёт код 200 | Документированное поведение Next.js для потоковых маршрутов; страница помечается `noindex` |

Полный перечень рисков — в отчётах по фазам и [`docs/OPEN_QUESTIONS.md`](docs/OPEN_QUESTIONS.md).
