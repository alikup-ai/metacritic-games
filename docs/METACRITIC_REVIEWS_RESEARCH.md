# Исследование: отзывы на Metacritic Games

**Дата:** 2026-09-08
**Метод:** живые HTTP-запросы, обычный User-Agent, без headless-браузера
**Статус:** исследование завершено, реализация не начата

Все факты ниже получены прямыми запросами и воспроизводимы. Предположения помечены
отдельно.

---

## 1. Executive summary

**Главная находка: HTML парсить не нужно.** Metacritic отдаёт отзывы через публичный
JSON API без авторизации:

```
https://backend.metacritic.com/reviews/metacritic/{critic|user}/games/{slug}[/platform/{platform}]/web
  ?offset=0&limit=10&filterBySentiment=all&sort=date
  &componentName=…&componentType=ReviewList
```

Он обнаружен в сериализованном состоянии страницы (`componentType=ReviewList`) и работает
напрямую. Это устраняет весь класс рисков, связанных с CSS-селекторами.

Пять решений, которые следуют из исследования:

| Вопрос | Ответ |
|---|---|
| Нужен ли headless-браузер | **Нет**. Обычный HTTP + JSON |
| Есть ли стабильный ID отзыва | **У пользовательских — да** (UUID). **У критических — нет** |
| Platform-specific ли отзывы | **Да, оба типа** — платформа задаётся сегментом пути |
| Возможен ли полный снимок | **Да**, но для популярных игр дорого (6595 отзывов = 33 запроса) |
| Возможны ли инкрементальные обновления | **Да** для пользовательских (`sort=date` + стабильный ID) |

**Главное ограничение:** critic-endpoint игнорирует `limit` и всегда отдаёт максимум
**10** записей, тогда как user-endpoint принимает `limit=200`. Это на порядок меняет
стоимость обхода критических отзывов.

## 2. Критические отзывы

### Endpoint

```
GET /reviews/metacritic/critic/games/{slug}/web?offset=0&limit=10&filterBySentiment=all&sort=date
```

### Структура записи

```json
{
  "quote": "Elden Ring is the real next step for souls-like standards…",
  "score": 100,
  "url": "https://areajugones.sport.es/videojuegos/analisis-elden-ring…",
  "date": "2022-02-23",
  "author": null,
  "authorSlug": null,
  "image": null,
  "publicationName": "Areajugones",
  "publicationSlug": "areajugones",
  "reviewedProduct": { "id": …, "title": "Elden Ring", "platform": { "id": …, "name": "PlayStation 5" } },
  "platform": "PlayStation 5"
}
```

| Поле | Наличие | Комментарий |
|---|---|---|
| `id` | **ОТСУТСТВУЕТ** | Ключевая проблема идентичности — см. §5 |
| `quote` | Есть | Выдержка, не полный текст рецензии |
| `score` | Есть | 0–100 |
| `url` | Обычно есть | **3 из 93 без URL**; не уникален (91 из 93) |
| `date` | Есть | ISO `YYYY-MM-DD` |
| `author` / `authorSlug` | Часто `null` | На Elden Ring — `null` у всех проверенных |
| `publicationName` / `publicationSlug` | Есть | **`publicationSlug` уникален: 93 из 93** |
| `platform` | Есть | Соответствует платформе endpoint'а |

### Ограничение размера страницы

`limit` **игнорируется**: при `limit=10/20/50/100` возвращается ровно 10 записей.
`offset` при этом работает корректно (`offset=90` → 3 записи из 93).

**Следствие:** полный обход 93 критических отзывов требует **10 запросов**, а не 1.

## 3. Пользовательские отзывы

### Endpoint

```
GET /reviews/metacritic/user/games/{slug}/web?offset=0&limit=200&filterBySentiment=all&sort=date
```

### Структура записи

```json
{
  "id": "ad709db3-0a82-4cb5-ad6b-d554ca40bfac",
  "quote": "Eines der Besten Spiele die ich jemals Spielen durfte…",
  "score": 10,
  "thumbsUp": null,
  "thumbsDown": null,
  "date": "2026-09-07",
  "author": "NextGas",
  "version": 1788771035295,
  "spoiler": false,
  "reviewedProduct": { …, "platform": { "id": 1500000128, "name": "PlayStation 5" } }
}
```

| Поле | Наличие | Комментарий |
|---|---|---|
| `id` | **Есть, UUID** | Стабилен — см. §5 |
| `version` | Есть | Похоже на метку времени изменения; кандидат для обнаружения правок |
| `score` | Есть | 0–10 |
| `author` | Есть | Имя пользователя |
| `spoiler` | Есть | Булев флаг |
| `thumbsUp` / `thumbsDown` | **`null` у всех 100 проверенных** | Поле присутствует, но не заполняется |
| `url` | **Отсутствует** | Прямой ссылки на отзыв нет |

`limit=200` принимается и возвращает 200 записей — на порядок эффективнее critic.

### Распределение оценок

Отдельного объекта распределения нет, но есть фильтр `filterBySentiment`:
`all` / `positive` / `negative` / `neutral`. Счётчики по каждому получаются как
`totalResults` соответствующего запроса.

## 4. Модель URL и пагинация

### Платформа — сегмент пути, а не параметр

```
…/critic/games/the-witcher-3-wild-hunt/web                        → 80  (по умолчанию)
…/critic/games/the-witcher-3-wild-hunt/platform/pc/web            → 33
…/critic/games/the-witcher-3-wild-hunt/platform/xbox-one/web      → 13
…/critic/games/the-witcher-3-wild-hunt/platform/nintendo-switch/web → 0
```

Параметры `?platform=`, `?filterByPlatform=`, `?platformId=` **игнорируются** — проверено,
все возвращают 80. Сегмент `/web` фиксирован (тип клиента); подстановка туда платформы
даёт 404.

### Проверка пагинации

| Свойство | Результат |
|---|---|
| Размер страницы (user) | до 200 |
| Размер страницы (critic) | **всегда 10**, `limit` игнорируется |
| Глубокий offset | `offset=6000` работает (200 OK, 5 записей) |
| Пересечение соседних страниц | **0** при `offset=0..20` и `20..40` |
| Повторный запрос | Порядок и ID идентичны |
| Пустая страница | `items: []`, `totalResults: 0`, HTTP 200 |
| Метаданные | `links.self/prev/next/first/last`, `data.totalResults` |
| Сортировки | `date` (Recently Added), `score` |
| Фильтры | `all`, `positive`, `negative`, `neutral` |

### Дрейф

В отличие от каталожного листинга (где Phase 1A обнаружила дрейф 5 из 20), у отзывов
дрейф **не наблюдался**: два одинаковых запроса дали идентичный порядок и состав.

> Оговорка: дрейф всё равно возможен при добавлении новых отзывов между запросами — при
> `sort=date` новая запись сдвинет остальные. Для активных игр (Elden Ring — отзывы
> появляются ежедневно) это реально. Защитой служит ключ по `id`, а не по позиции.

## 5. Идентичность и идемпотентность

### Пользовательские отзывы — надёжный ключ

Проверка на игре со 112 отзывами (полная выборка, две сортировки):

- множества `id` **идентичны** (112 = 112, пересечение 112);
- у одного и того же `id` совпали `quote`, `score`, `date`, `author`, `version`.

**Вывод: `id` (UUID) пригоден как внешний ключ.** Естественный ключ хранения:
`(game_id, source_review_id)`.

### Критические отзывы — ключа нет, нужен составной

`id` отсутствует. Проверка всех 93 отзывов Elden Ring:

| Кандидат в ключ | Уникальность | Пригодность |
|---|---|---|
| `url` | **91 из 93** + 3 записи без URL | ❌ Не годится |
| `publicationSlug` | **93 из 93** | ✅ Годится |
| `publicationSlug` + `date` | 93 из 93 | ✅ Устойчивее |

Логика подтверждает наблюдение: издание публикует **одну** рецензию на игру для платформы.

**Рекомендуемый ключ:** `(game_id, platform, publication_slug)`.

> **Риск.** Ключ производный, а не выданный источником. Если издание опубликует вторую
> рецензию (переоценка после патча) — второй записи не будет, первая перезапишется.
> Вероятность низкая, последствие — потеря одной рецензии, не порча каталога.

## 6. Семантика платформ

**Оба типа отзывов platform-specific.** Это уточняет вывод ADR-0008.

Проверка на Witcher 3 (Metascore: PC 93, Xbox One 91, PS4 92):

| Платформа | critic `totalResults` | user `totalResults` |
|---|---|---|
| (по умолчанию) | 80 | 2747 |
| `pc` | **33** | 3180 |
| `xbox-one` | **13** | 468 |
| `playstation-4` | **80** | 2747 |
| `nintendo-switch` | 0 | 37 |

Числа критиков (33 / 13 / 80) **точно совпадают** со счётчиками рецензий на карточке игры,
найденными в Phase 1A. Это независимое подтверждение корректности.

### Что это НЕ меняет

Вывод ADR-0008 остаётся в силе: **агрегированный Userscore публикуется общий по игре**,
и `userscore_scope = 'overall'` корректен. Platform-specific здесь — сами *отзывы*, а не
опубликованная агрегированная оценка.

Вычислять собственный средний Userscore по платформе из отзывов по-прежнему **нельзя**
выдавать за оценку Metacritic (ADR-0008, значение `derived` зарезервировано).

### Endpoint без платформы

Возвращает данные **основной** платформы (для Witcher 3 — PS4), а не объединение всех.
Полный охват требует обхода по каждой платформе игры.

## 7. Семантика инкрементальных обновлений

### Пользовательские отзывы — инкремент возможен

`sort=date` + стабильный `id` + поле `version` дают рабочую схему:

1. запросить первую страницу с `sort=date`;
2. идти вглубь, пока встречаются неизвестные `id`;
3. остановиться, когда страница целиком состоит из известных.

Поле `version` (например, `1788771035295`) выглядит как метка времени изменения и может
служить признаком правки текста. **Не проверено:** изменение `version` при редактировании
отзыва наблюдать не удалось — потребовалось бы дождаться реальной правки.

### Критические отзывы — только полный снимок

Без `id` инкремент ненадёжен. Но их мало (9–93 на игру), поэтому полный обход дешевле
любой инкрементальной схемы. При 10 записях на запрос: 93 отзыва = 10 запросов.

### Удаление и скрытие

Признака `deleted`/`hidden` в ответе нет. Удалённый отзыв, предположительно, просто
исчезает из выдачи и уменьшает `totalResults`.

**Не проверено** — требует наблюдения за конкретным отзывом во времени. Практическое
следствие: обнаружить удаление можно только сравнением полного снимка с сохранённым.

## 8. Отказы и деградация

| Ситуация | Поведение | Проверено |
|---|---|---|
| Игра без отзывов | HTTP **200**, `items: []`, `totalResults: 0` | ✅ `tiny-eden` |
| Только критические, без пользовательских | 200 + 9 / 200 + 0 | ✅ `halloween-the-game` |
| Несуществующая игра | HTTP **404** | ✅ `no-such-game-xyz-12345` |
| Платформа без отзывов | 200, `totalResults: 0` | ✅ Witcher 3 / Switch (critic) |
| Offset за пределами | 200, меньше записей | ✅ `offset=6000` |
| `author` отсутствует | `null` | ✅ Все critic Elden Ring |
| `url` отсутствует | Поле пустое | ✅ 3 из 93 |
| `thumbsUp/Down` | `null` у всех | ✅ 100 проверенных |

**Важно:** отсутствие отзывов — это `200`, а не ошибка. Обработка должна отличать
«отзывов нет» (штатно) от «запрос не удался».

## 9. Ограничение частоты

| Проверка | Результат |
|---|---|
| 12 запросов подряд без пауз | **Все 200**, ни одного 429 |
| Заголовки `ratelimit-*`, `retry-after` | Отсутствуют |
| Запрос без `User-Agent` | **200** — UA не обязателен |
| `server` | `cloudflare` |
| Отличие от каталожного endpoint | Другой хост (`backend.` вместо `www.`), но поведение схожее |

Жёсткого лимита не обнаружено. Тем не менее рекомендую сохранить действующее ограничение
**≤1 запроса в секунду** и общий token bucket: отсутствие лимита в наблюдении не означает
его отсутствия вообще, а обход защит не рассматривается.

### Оценка стоимости обхода

| Сценарий | Запросов |
|---|---|
| Критические, типичная игра (≤10 отзывов) | 1 |
| Критические, Elden Ring (93) | 10 |
| Пользовательские, первая страница (200) | 1 |
| Пользовательские, полный снимок Elden Ring (6595) | **33** |
| Обе категории, одна платформа, разумный лимит | **2–4** |

При 20 играх в час и лимите в 1 страницу каждого типа: ~40–80 запросов на запуск, что
укладывается в бюджет вежливости.

## 11. Открытые вопросы

| # | Вопрос | Почему не закрыт | Предложение |
|---|---|---|---|
| RQ-1 | Меняется ли `version` при правке отзыва | Требует наблюдения за реальной правкой | Сохранять `version`; проверить на данных после первого месяца |
| RQ-2 | Как выглядит удалённый отзыв | Требует наблюдения во времени | Считать исчезновение из полного снимка признаком удаления |
| RQ-3 | Стабильны ли `id` месяцами | Проверено в пределах сессии | Мониторить долю «исчезнувших» id |
| RQ-4 | Есть ли скрытый rate limit | 12 запросов — недостаточная выборка | Сохранить ≤1 rps, следить за 429 |
| RQ-5 | Является ли API публичным контрактом | Не документирован Metacritic | Оставить HTML-парсер как запасной путь |
| RQ-6 | Сколько отзывов забирать на игру | Продуктовое решение | Предлагаю 1 страницу каждого типа (OQ-11) |
| RQ-7 | Обходить ли все платформы | Умножает стоимость на число платформ | Предлагаю только основную на MVP |

**RQ-5 — главный архитектурный риск.** API не документирован и может измениться без
предупреждения. Предлагаю: адаптер как основной путь, HTML-парсер (уже работающий с
Phase 1A) как задокументированный fallback, и golden-file тесты на обоих.

## 12. Рекомендуемая архитектура

Изменений схемы БД **не требуется** — таблицы `review_snapshots` и `review_summaries`
из Phase 0 подходят. Уточнения:

```
ReviewSource (порт в domain)
     ↑
MetacriticReviewApiAdapter        ← основной путь (JSON API)
MetacriticReviewHtmlAdapter       ← fallback (парсер Phase 1A)
```

**Ключи хранения:**

```
user   → (game_id, source_review_id)                    -- UUID из API
critic → (game_id, platform, publication_slug)          -- составной, id отсутствует
```

**Стратегия обхода (предложение):**

- одна платформа (основная) на MVP;
- критические: полный обход, `limit` не задавать (всё равно 10);
- пользовательские: первая страница `limit=50`, `sort=date`;
- отсутствие отзывов — валидный результат, не ошибка;
- fingerprint снимка для fingerprint-gate LLM (DR-4) считать по множеству ключей + оценок.

**Что НЕ делать:**

- не вычислять Userscore по платформам и не выдавать за оценку Metacritic (ADR-0008);
- не полагаться на `url` как ключ критического отзыва (не уникален);
- не считать отсутствие отзывов ошибкой;
- не обходить все платформы на MVP без отдельного решения по бюджету запросов.
