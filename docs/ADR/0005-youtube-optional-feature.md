# ADR-0005: YouTube-интеграция как опциональная возможность

**Статус:** Принято
**Дата:** 2026-09-07
**Решение принял:** Product/Tech Lead
**Связано с:** OQ-5

---

## Контекст

Дополнительная часть 1 требует: найти летсплеи на YouTube, взять самый популярный, перевести
рассказ блогера в текст, сделать заключение и добавить его к информации об игре со ссылкой
на ролик.

Решение Tech Lead:
- реализовать **после** обязательной части и мониторинга;
- управлять **feature flag**;
- ошибка/отсутствие transcript **никогда** не ломает основной pipeline;
- обязательна graceful degradation.

### Почему это самая рискованная часть задания

Шаг «перевести рассказ в текст» технически труден по независящим от нас причинам:

1. У многих игровых видео **нет** ручных субтитров.
2. Автоматические субтитры **не отдаются** официальным YouTube Data API.
3. Сторонние библиотеки-скрейперы субтитров неофициальны, хрупки и находятся в серой зоне ToS.
4. ASR (Whisper) работает всегда, но требует скачивания аудио (нарушает ToS YouTube),
   стоит денег и занимает минуты на ролик.
5. YouTube Data API: квота 10 000 единиц/сутки, поиск стоит 100 единиц → ~100 поисков/сутки.
   При 20 играх в час квота исчерпается примерно за 5 часов.

Иначе говоря, ни один вариант не даёт одновременно «надёжно», «легально» и «дёшево».

## Рассмотренные варианты

### A. Только официальные субтитры
- ➕ Легально, бесплатно.
- ➖ Часто пусто → функция выглядит нерабочей.

### B. Сторонний скрейпер субтитров
- ➕ Обычно работает, достаёт авто-субтитры.
- ➖ Неофициально, хрупко, серая зона ToS.

### C. Скачивание аудио + ASR
- ➕ Всегда даёт результат, буквально выполняет требование.
- ➖ Против ToS YouTube, платно, медленно (минуты на ролик).

### D. Каскад с честной деградацией (выбрано)
Попробовать A → при неудаче B → иначе заключение по метаданным с **явной маркировкой
источника**.

- ➕ Пытается выполнить требование по-настоящему.
- ➕ Никогда не блокирует обработку игры.
- ➕ Не выдаёт метаданные за расшифровку аудио.
- ➖ Часть игр получит заключение более низкого качества.

## Решение

Принят **вариант D** с обязательным feature flag.

### Изоляция

Стадия `youtube` — **обогащающая**, не критичная:

```
fetchGame     → критичная  (провал = игра не обработана)
fetchReviews  → критичная
summarize     → обогащающая
similar       → обогащающая
youtube       → обогащающая (+ feature flag)
```

Провал стадии YouTube приводит к записи `video_status = 'failed'` и продолжению работы.
Игра сохраняется и отображается. Это прямая реализация требования «отсутствие transcript не
блокирует обработку игры».

### Feature flag

`FEATURE_YOUTUBE_ENABLED` (по умолчанию `false`):
- выключен → адаптер не подключается в composition root, ключи API не требуются, сервис
  полностью работоспособен;
- включён → стадия добавляется в конец пайплайна.

Флаг проверяется на уровне сборки зависимостей, а не условиями внутри бизнес-логики —
доменный слой о YouTube не знает вовсе (ADR-0001).

### Прозрачность источника

`transcript_source` сохраняется явно и **показывается в UI**:

| Значение | Что показывает интерфейс |
|---|---|
| `official_captions` | «По официальным субтитрам» |
| `auto_captions` | «По автоматическим субтитрам» |
| `metadata_only` | «По описанию видео (расшифровка недоступна)» |

Сервис **никогда** не подразумевает, что расшифровал речь, если этого не было. Это то же
правило честности, что и запрет подмены developer на publisher (ADR-0003).

### Управление квотой

- Кэширование результатов поиска по игре: повторные обходы не тратят квоту.
- Счётчик квоты в сутки; при исчерпании стадия отключается до следующих суток,
  остальной пайплайн продолжает работу.
- Ошибка 403 quota обрабатывается как «мягкое отключение», а не как сбой run.

## Последствия

**Положительные**
- Обязательная часть полностью независима от самой рискованной опциональной.
- Функцию можно отключить одним флагом, если она нестабильна на демо.
- Пользователь видит, на чём основано заключение.

**Отрицательные**
- Часть игр получит заключение по метаданным, а не по расшифровке.
- Квота ограничивает охват примерно 100 играми в сутки.

**Принятый компромисс:** честная деградация с явной маркировкой предпочтительнее и
недостоверного результата, и полного отсутствия функции.

## Открытый вопрос

Если требуется именно настоящая ASR-расшифровка (с принятием стоимости, задержки и рисков
ToS) — это отдельное решение Product/Tech Lead. Текущая архитектура позволяет добавить
ASR-адаптер как ещё один шаг каскада без изменения domain-слоя.

## Проверяемость

- Тест: при выключенном флаге пайплайн работает и не требует ключей YouTube.
- Тест: ошибка YouTube API не меняет статус игры на неуспешный.
- Тест: отсутствие субтитров → `metadata_only` + соответствующая пометка в UI.

## Дополнение: внешний поставщик расшифровок (проверено на реальном API)

### Почему понадобился

Открытая точка `youtube.com/api/timedtext` перестала отдавать данные. Проверено
тремя независимыми способами: пустое тело (HTTP 200, 0 байт) для целевого ролика,
для заведомо субтитрированных роликов и даже для запроса `type=list`. При этом
Data API подтверждает `caption: true` и перечисляет дорожки. YouTube требует
параметры подписи, выдаваемые только плееру.

Официальный `captions.download` не подходит: требует OAuth с правами владельца
ролика, то есть для чужих видео недоступен в принципе.

### Почему Supadata

Из рассмотренных единственный закрывает оба случая: берёт готовые субтитры
(1 кредит) и при их отсутствии распознаёт речь сам (2 кредита/минуту).
TranscriptAPI в режиме `asr` возвращает лишь существующие авто-дорожки YouTube.
AssemblyAI принимает только прямую ссылку на медиафайл — для YouTube потребовался
бы обход защит, что недопустимо.

### Архитектура

```
TranscriptPort (domain, без изменений)
├── YouTubeTranscriptAdapter    — субтитры YouTube, бесплатно
├── SupadataTranscriptAdapter   — внешний сервис, платно
└── FallbackTranscriptAdapter   — цепочка, сам реализует порт
```

Слой application видит один поставщик и о цепочке не знает. Порядок задаётся при
сборке: бесплатный источник пробуется первым, платный — только при его неудаче.

### Семантика transcript_source

| Значение | Смысл |
|---|---|
| `official` | Ручные субтитры YouTube |
| `auto` | Авто-субтитры YouTube |
| `external_captions` | Расшифровка от внешнего сервиса |
| `external_asr` | Распознавание речи внешним сервисом |
| `metadata_only` | Ролик найден, расшифровки нет |
| `none` | Ролика нет |

**`external_asr` пока не используется.** Ответ Supadata не содержит поля,
различающего готовые субтитры и собственное распознавание: в схеме есть только
`content`, `lang` и `availableLangs`. Происхождение не выдумывается — применяется
более осторожное `external_captions`. Значение останется незанятым, пока сервис
не начнёт различать источник.

### Исправленный дефект выбора языка

Прежняя реализация перебирала только `en` и `ru`, тогда как у проверенного ролика
доступны **только немецкие** дорожки. Теперь язык выбирается из фактического
списка (`captions.list`, доступен по обычному ключу): en → ru → язык из
конфигурации → первый доступный.

### Настройка

```
SUPADATA_API_KEY=<ключ>          # без него остаётся только timedtext
SUPADATA_TIMEOUT_MS=30000
TRANSCRIPT_FALLBACK_LANGUAGE=    # третий приоритет после en и ru
```

Отсутствие ключа не является ошибкой: приложение стартует, поставщик не
собирается, в журнал пишется пояснение.

### Поведение при сбоях

| Ситуация | Категория | Повтор |
|---|---|---|
| 401 / 403 | `client_error` | нет — ключ не тот |
| 402, 429, `limit-exceeded` | `quota_exceeded` | нет — лимит |
| 404 | `not_found` | нет |
| 5xx | `unavailable` | да |
| Таймаут | `timeout` | да |
| 206 | не ошибка | расшифровки нет, идём дальше |

Сбой любого поставщика не прерывает цепочку и не роняет обработку игры: ролик
сохраняется со ссылкой и метаданными.

### Стоимость

При 20 видео в сутки и готовых субтитрах — 600 кредитов в месяц, тариф Pro
($17/мес, 3000 кредитов). Отбор предпочитает ролики с субтитрами
(`contentDetails.caption`), поэтому дорогое распознавание речи требуется редко.

### Ограничения

- Происхождение расшифровки различить нельзя (см. выше).
- Один внешний сервис без второго запасного.
- Расшифровка не хранится: только отпечаток, метаданные и разбор.
