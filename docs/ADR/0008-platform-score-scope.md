# ADR-0008: Раздельный score_scope для Metascore и Userscore

**Статус:** Принято
**Дата:** 2026-09-07
**Основание:** исследование `docs/METACRITIC_PLATFORM_SCORES.md`
**Связано с:** OQ-18

---

## Контекст

ТЗ требует хранить «Платформа + Metascore + Userscore», где платформ может быть несколько.
Product/Tech Lead потребовал: **не создавать ложную связь score → platform** и провести
исследование до реализации, не полагаясь на предположения о HTML/CSS.

## Результат исследования

Проверены две игры с несколькими платформами **[ПРОВЕРЕНО]**:

| Игра | Платформа | Metascore |
|---|---|---|
| elden-ring | PC / Xbox Series X / PS5 | 94 / 96 / 96 |
| the-witcher-3 | PC / Xbox One / PS4 | 93 / 91 / 92 |

**Metascore:** связь с платформой **доказана** — значения различаются между платформами и
находятся в одном DOM-контейнере с названием платформы. Если бы разметка дублировала общую
оценку, значения совпадали бы.

**Userscore:** публикуется **только общий** по игре (Elden Ring — 8.4). Разбивки по
платформам Metacritic не предоставляет.

Дополнительно: платформа может присутствовать без оценки (`tbd`) — нормальное состояние.

## Рассмотренные варианты

### A. Один общий `score_scope` на строку
- ➖ Вынуждает выбрать одно из двух: либо занизить достоверность Metascore (который
  доказанно платформенный), либо завысить достоверность Userscore.
- ❌ Приводит к ложной связи для одной из метрик.

### B. Раздельные `metascore_scope` и `userscore_scope` (выбрано)
- ➕ Каждая метрика описывается честно.
- ➕ UI может показать «оценка критиков — по платформе, оценка игроков — общая».
- ➖ Два поля вместо одного.

### C. Вычислять Userscore по платформе из отзывов
Технически возможно: в payload каждый отзыв содержит `platform`.
- ➖ Результат — **наша** агрегация, а не оценка Metacritic. Выдача её за официальную —
  ровно та ложная связь, которая запрещена.
- ❌ Отклонено для MVP.

## Решение

Принят **вариант B**.

```sql
metascore        SMALLINT NULL,     -- NULL при 'tbd'
metascore_scope  TEXT NOT NULL,     -- 'platform' | 'overall' | 'overall_fallback' | 'derived'
userscore        NUMERIC(3,1) NULL,
userscore_scope  TEXT NOT NULL,     -- по умолчанию 'overall'
```

Значения `score_scope`:

| Значение | Смысл | Применение |
|---|---|---|
| `platform` | Оценка относится именно к этой платформе | Metascore (доказано) |
| `overall` | Источник **публикует только общую** оценку по игре | Userscore — штатное состояние |
| `overall_fallback` | Источник, вероятно, даёт оценку по платформам, но связать **не удалось** | Деградация, сигнал о смене разметки |
| `derived` | Рассчитана нами | Зарезервировано, на MVP не используется |

> **Уточнение (миграция 005).** Изначально `overall_fallback` обозначал оба состояния.
> Это скрывало важное различие: «Metacritic так устроен» и «мы не смогли распарсить» требуют
> разной реакции. Рост доли `overall_fallback` — сигнал о поломке парсера; доля `overall`
> постоянна и внимания не требует. Один термин делал бы деградацию невидимой.

### Обязательство перед пользователем

При `overall` и `overall_fallback` интерфейс **обязан** явно указать, что оценка общая по игре, а не
платформенная. Молчаливое отображение общей оценки в строке платформы создаёт у пользователя
ложное впечатление — это и есть запрещённая ложная связь, независимо от того, что в БД
проставлен корректный scope.

### Разделение метрики и её отсутствия

`metascore = NULL` при `metascore_scope = 'platform'` означает «платформа известна, оценки
пока нет (`tbd`)». Это отличается от «оценка есть, но не платформенная». Оба состояния
различимы в схеме.

## Последствия

**Положительные**
- Требование ТЗ выполняется без искажения данных.
- Достоверность каждой метрики выражена в схеме, а не в комментарии.
- `derived` позволяет добавить вычисленный Userscore позже без миграции.

**Отрицательные**
- UI усложняется пометкой источника оценки. Принято: честность важнее лаконичности.

## Проверяемость

- Тест: парсер `elden-ring` возвращает PC 94, XSX 96, PS5 96 с scope `platform`.
- Тест: платформа с `tbd` сохраняется с `metascore = NULL`.
- Тест: Userscore записывается с `overall`.
- Тест: при неудачной привязке Metascore используется `overall_fallback`, а не `overall`.
- Тест: UI отображает пометку при `overall` и `overall_fallback`.
