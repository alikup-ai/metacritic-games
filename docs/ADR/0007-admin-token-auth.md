# ADR-0007: Аутентификация Force Run через статический admin-токен

**Статус:** Принято
**Дата:** 2026-09-07
**Решение принял:** Product/Tech Lead
**Связано с:** OQ-8

---

## Контекст

Дополнительная часть 2 требует кнопку принудительного запуска обработки. Эндпоинт публично
доступен и запускает дорогие операции: scraping и платные LLM-вызовы. Без защиты любой
посетитель или поисковый робот может исчерпать квоты и бюджет.

При этом полноценная система пользователей несоразмерна тестовому заданию.

## Решение

Статический **`X-Admin-Token`** для demo-окружения.

Требования (обязательны к исполнению):

| Требование | Реализация |
|---|---|
| Токен только в environment | `ADMIN_TOKEN`, валидация при старте |
| Не хранится в Git | `.env` в `.gitignore` |
| Не публикуется в README открыто | README описывает механизм, не значение |
| `.env.example` — только placeholder | `ADMIN_TOKEN=<generate-a-random-64-char-token>` |
| `POST /api/runs` требует токен | Middleware на write-эндпоинтах |
| Rate limit | Ограничение на write-эндпоинты |
| Неверный токен → 401/403 | 401 при отсутствии, 403 при неверном |
| Constant-time сравнение | `crypto.timingSafeEqual` |
| Токен не логируется | Явное исключение заголовка в логгере |

### Почему constant-time сравнение

Обычное сравнение строк (`===`) завершается на первом несовпавшем символе. Разница во
времени ответа теоретически позволяет подбирать токен посимвольно. `timingSafeEqual`
выполняется за постоянное время независимо от того, где находится расхождение.

Практический риск для demo невысок, но требование зафиксировано Tech Lead, а стоимость
корректной реализации — одна строка кода.

**Деталь реализации:** `timingSafeEqual` требует буферов одинаковой длины и бросает
исключение при несовпадении. Поэтому сначала сравниваются хеши фиксированной длины
(SHA-256 от токена), затем — сами буферы. Иначе длина токена утекала бы через исключение.

### Коды ответов

| Ситуация | Код |
|---|---|
| Заголовок отсутствует | `401 Unauthorized` |
| Токен неверный | `403 Forbidden` |
| Превышен rate limit | `429 Too Many Requests` |
| Запуск уже идёт | `409 Conflict` |
| Принято | `202 Accepted` |

`409` возвращается **после** успешной аутентификации: неаутентифицированный клиент не должен
узнавать о состоянии системы.

### Что осознанно не делается

JWT, OAuth, сессии, роли, пользователи — несоразмерны demo и увеличивают поверхность атаки
без пользы для оценки задания.

### Доступ проверяющего

README описывает механизм и указывает, что токен передаётся отдельно. Значение **не**
публикуется в репозитории. Если требуется дать проверяющему доступ к кнопке — токен
передаётся вне репозитория (это отдельное решение Product/Tech Lead).

## Последствия

**Положительные**
- Дорогие операции защищены.
- Реализация — несколько десятков строк.
- Секрет не попадает в репозиторий (соответствует общему правилу по секретам).

**Отрицательные**
- Один общий токен: нет разграничения и аудита по пользователям. Для demo приемлемо.
- Ротация — только перезапуском с новым значением.

## Проверяемость

- Тест: `POST /api/runs` без заголовка → 401.
- Тест: с неверным токеном → 403.
- Тест: с верным токеном → 202.
- Тест: превышение лимита → 429.
- Тест: токен отсутствует в выводе логгера.
- Тест: `.env` не отслеживается Git.
