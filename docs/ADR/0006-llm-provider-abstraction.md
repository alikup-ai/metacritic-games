# ADR-0006: Абстракция LLM-провайдера

**Статус:** Принято
**Дата:** 2026-09-07
**Решение принял:** Product/Tech Lead
**Связано с:** OQ-6

---

## Контекст

Сервису нужны три LLM-задачи: резюме отзывов критиков, резюме отзывов пользователей и
заключение по транскрипту летсплея. Модели быстро устаревают и дешевеют, а привязка
бизнес-логики к конкретному SDK делает замену дорогой.

## Решение

- **Модель для MVP:** Claude Haiku-класса — задачи представляют собой суммаризацию
  предоставленного текста, а не сложное рассуждение.
- **Конкретная модель выносится в конфигурацию** (`LLM_MODEL`), код от неё не зависит.
- **Порт `LlmProvider`** объявлен в domain; адаптер живёт в infrastructure.
- Замена provider/model **не требует** изменений в domain/application.
- Для тестов создаётся **fake/mock** реализация порта.
- API key — только через environment variable.
- **Запрещено логировать** API key и полный `Authorization` header.

### Контракт порта

```typescript
// domain — без импортов SDK
interface LlmProvider {
  complete(request: LlmRequest): Promise<LlmResult>;
}

interface LlmRequest {
  promptVersion: string;      // сохраняется вместе с результатом
  system: string;
  user: string;
  schema: JsonSchema;         // структурированный вывод
  maxTokens: number;
}

interface LlmResult {
  content: unknown;           // валидируется по schema
  model: string;              // фактически использованная модель
  tokensIn: number;
  tokensOut: number;
}
```

`model` возвращается **фактический**, а не запрошенный, и сохраняется в
`review_summaries.model` — иначе после смены модели нельзя понять, чем сгенерирована
конкретная запись.

### Fake-провайдер для тестов

`FakeLlmProvider` возвращает детерминированные ответы по схеме. Это даёт:
- unit- и integration-тесты без сети и без затрат;
- воспроизводимость CI;
- возможность тестировать пути ошибок (таймаут, невалидный JSON, отказ).

### Безопасность логирования

Логируются: `model`, `promptVersion`, число токенов, длительность, `game_slug`.
**Не логируются:** ключ, заголовки авторизации. В runtime-логи
(`logs/ai/runtime/llm-calls.jsonl`) пишутся промпт и ответ — они не содержат секретов
by design (ключ передаётся только в заголовке HTTP, который не сериализуется).

## Последствия

**Положительные**
- Смена модели — правка переменной окружения.
- Смена провайдера — один новый адаптер.
- Тесты быстрые, бесплатные, детерминированные.
- Ключ не может попасть в логи (ADR-совместимо с OQ-19).

**Отрицательные**
- Дополнительный слой абстракции; провайдер-специфичные возможности (кэширование промптов)
  недоступны без расширения контракта. Принято осознанно: переносимость важнее.

## Проверяемость

- Тест: domain/application не импортируют SDK провайдера (`dependency-cruiser`).
- Тест: прогон пайплайна на `FakeLlmProvider` без сети.
- Тест: ключ отсутствует в выводе логгера.
