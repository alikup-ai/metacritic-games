# ADR-0003: Идентичность игры и разделение developer/publisher

**Статус:** Принято
**Дата:** 2026-09-07
**Решение принял:** Product/Tech Lead
**Связано с:** OQ-3, OQ-4

---

## Контекст

Нужен стабильный ключ, по которому игра распознаётся при повторных обходах: ТЗ требует
**обновлять** существующую игру, а не создавать дубликат. Отдельно требуется поле
**Разработчик (developer)**.

## Часть 1 — Идентичность

### Рассмотренные варианты

**A. Только Metacritic slug как PK** — просто, но привязывает всю схему к одному источнику и
ломается, если Metacritic изменит slug.

**B. UUID как PK + `(source, source_slug)` как natural key (выбрано).**

**C. title + год** — title не уникален (ремейки, переиздания, региональные версии).

**D. title + платформа** — раздробило бы одну игру на несколько строк и сломало требование
о нескольких платформах у одной игры (FR-6).

### Решение

- **Внутренний PK:** `UUID` — стабилен, не зависит от источника, безопасен во внешних URL.
- **Внешний natural key:** `UNIQUE (source, source_slug)`, `source = 'metacritic'`.
- **Title как ключ не используется никогда.**

Поле `source` заложено заранее: добавление второго источника не потребует миграции PK и
переписывания связей.

Upsert:
```sql
INSERT INTO game (...) VALUES (...)
ON CONFLICT (source, source_slug) DO UPDATE SET ...
```
`first_seen_at` сохраняется, `last_updated_at` обновляется.

## Часть 2 — Developer vs Publisher

### Исследование (2026-09-07) — проведено до принятия решения

По требованию «не invent selectors: сначала исследование» проверены 4 страницы
**[ПРОВЕРЕНО]**:

| Игра | developer (DOM) | publisher (JSON-LD) |
|---|---|---|
| `elden-ring` | From Software | Bandai Namco Games, **From Software** |
| `halloween-the-game` | IllFonic | Gun Interactive, **IllFonic** |
| `hot-wheels-infinite-rush` | Milestone S.r.l | Milestone S.r.l |
| `the-blood-of-dawnwalker` | **отсутствует** | Bandai Namco Games |

**Выводы:**

1. **Developer доступен отдельно** — контейнер `data-testid="hero-summary-developer"`
   со ссылкой вида `/company/from-software/`. Присутствовал на 4/4 страницах.
   `data-testid` — атрибут для автотестов, меняется реже, чем CSS-классы.
2. **JSON-LD `publisher` непригоден как developer.** Он возвращает смешанный список: для
   Elden Ring — и издателя (Bandai Namco), и разработчика (From Software), без различения
   ролей. Подстановка publisher вместо developer дала бы фактически неверные данные.
3. **Пустой developer — реальный случай.** `the-blood-of-dawnwalker` не имеет developer в
   разметке. Ветка «неизвестно» обязательна, а не гипотетична.

### Решение

- Извлекать developer из `data-testid="hero-summary-developer"`.
- Извлекать publisher из JSON-LD, хранить отдельным полем (`TEXT[]`).
- **Никогда не подменять developer publisher'ом.** Запрет обеспечивается на уровне кода:
  функции разные, общего fallback между ними нет.
- Если developer не определён → `developer = NULL`, `developer_status = 'unknown'`,
  запись в ingestion log с указанием слага.
- UI при `unknown` отображает «Разработчик не указан», publisher показывается **только**
  в собственном поле «Издатель».

### Устойчивость к изменениям

`data-testid` — единственная точка, зависящая от вёрстки. Меры:
- Golden-file тест на зафиксированной HTML-фикстуре ловит изменение в CI.
- Массовый рост `developer_status='unknown'` — сигнал мониторинга о смене разметки,
  а не тихая деградация данных.

## Последствия

**Положительные**
- Требование ТЗ выполняется корректно, без выдачи издателя за разработчика.
- Отсутствие данных фиксируется явно и наблюдаемо.
- UUID изолирует схему от изменений на стороне Metacritic.

**Отрицательные**
- Одно поле зависит от DOM-селектора (JSON-LD его не содержит) — принято осознанно,
  прикрыто тестами и мониторингом.

## Проверяемость

- Тест: повторная обработка того же слага обновляет строку, не создаёт вторую.
- Тест: при отсутствии developer поле `NULL`, статус `unknown`, есть запись в логе.
- Тест: publisher никогда не попадает в поле developer.
