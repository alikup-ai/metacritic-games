# Definition of Done — Metacritic Games Service

**Версия:** 1.0
**Дата:** 2026-09-07

Критерии обязательны. Задача не считается выполненной при невыполнении любого применимого
пункта. Часть проверок автоматизирована в CI, часть требует ручного контроля.

---

## 1. Общие критерии (для любой задачи)

### Код
- [ ] Соответствует разделению domain / application / infrastructure (ADR-0001)
- [ ] `domain` не импортирует infrastructure, SDK, драйверы БД
- [ ] Внешние интеграции — только через порты
- [ ] Проверка типов проходит (`tsc --noEmit`), без `any` без обоснования
- [ ] Lint и форматирование без ошибок
- [ ] `dependency-cruiser` не находит нарушений границ

### Тесты
- [ ] Доменная логика покрыта unit-тестами без БД и сети
- [ ] Работа с БД покрыта integration-тестами
- [ ] Тесты детерминированы (без зависимости от времени, сети, порядка)
- [ ] Внешние сервисы замоканы (в т.ч. `FakeLlmProvider`, ADR-0006)

### Документация
- [ ] Значимые архитектурные решения оформлены ADR
- [ ] Новые допущения внесены в документацию
- [ ] `OPEN_QUESTIONS.md` актуален
- [ ] Документы не противоречат друг другу

---

## 2. Критерии безопасности (обязательны всегда)

### Секреты — общее правило заказчика

Никакие реальные **API keys, passwords, admin tokens, database credentials, cookies,
session tokens** не должны попадать в:

- [ ] Git (история включительно)
- [ ] README
- [ ] тестовые fixtures
- [ ] screenshots
- [ ] AI logs
- [ ] финальный submission

Проверка:
- [ ] `.env` в `.gitignore`
- [ ] `.env.example` содержит только имена переменных и placeholder'ы
- [ ] secret scan не находит совпадений
- [ ] API key и `Authorization` не логируются (ADR-0006)
- [ ] `X-Admin-Token` не логируется (ADR-0007)

### Обработка ввода
- [ ] Все внешние данные считаются недоверенными (Metacritic, YouTube, ответы LLM)
- [ ] Параметры запросов валидируются схемой
- [ ] SQL — только параметризованный
- [ ] Вывод экранируется; `dangerouslySetInnerHTML` не используется
- [ ] URL видео проверяются по allowlist хостов

---

## 3. Критерии надёжности

### Внешние HTTP-вызовы
- [ ] Задан timeout
- [ ] Настроен retry с backoff и jitter
- [ ] `403` → прекращение, без повторов
- [ ] `429` → учёт `Retry-After`
- [ ] `5xx` → повтор как транзиентной ошибки
- [ ] Соблюдается общий rate limit
- [ ] Ошибки классифицируются, а не подавляются

### Фоновые задачи
- [ ] Операция идемпотентна
- [ ] Повторный запуск не создаёт дубликатов
- [ ] Частично выполненная работа возобновляется, а не начинается заново
- [ ] Сбой одного элемента не роняет батч
- [ ] Обогащающие стадии не блокируют сохранение игры

---

## 4. Критерии по фазам

### Фаза 0 — Каркас
- [ ] `docker compose up` поднимает сервис
- [ ] Миграции применяются автоматически
- [ ] `/healthz` и `/readyz` отвечают
- [ ] CI зелёный; нарушение границ слоёв роняет сборку
- [ ] Конфигурация валидируется при старте (падение при неверной)

### Фаза 1 — Ingestion
- [ ] За запуск обрабатывается 20 **claimed** игр (ADR-0004)
- [ ] Новый день начинается с New Releases
- [ ] После исчерпания New Releases — переход к See All
- [ ] Курсор страницы сохраняется
- [ ] Пересечение страниц листинга не приводит к пропускам (ADR-0002)
- [ ] Существующая игра обновляется, не дублируется
- [ ] Параллельный claim одного слага → успешен ровно один
- [ ] Повторный запуск в тот же день не создаёт второй claim
- [ ] Истёкший lease возвращает игру в пул без дубля
- [ ] Перезапуск после части стадий → продолжение
- [ ] `developer = null` + `unknown` + запись в ingestion log при отсутствии (ADR-0003)
- [ ] Publisher никогда не записывается в поле developer

### Фаза 2 — Web UI
- [ ] Список, карточка, фильтр по платформам, поиск, сортировка работают
- [ ] Состояние фильтров в URL
- [ ] При `developer_status='unknown'` показывается «Разработчик не указан»
- [ ] При `userscore_scope='overall'` / `'overall_fallback'` есть явная пометка (ADR-0008)
- [ ] Есть пустые состояния, состояния загрузки и ошибок
- [ ] p95 списка < 300 мс

### Фаза 3 — Отзывы и LLM
- [ ] Раздельные резюме по критикам и пользователям
- [ ] Структурированный вывод, валидируемый схемой
- [ ] Fingerprint-gate: при неизменных отзывах вызов не выполняется
- [ ] Отсутствие отзывов не приводит к вызову LLM и не считается ошибкой
- [ ] Сохраняются `model`, `prompt_version`, `source_review_count`
- [ ] Все вызовы записаны в runtime-лог
- [ ] Тесты проходят на `FakeLlmProvider` без сети

### Фаза 4 — Похожие игры
- [ ] Похожие игры отображаются, клик открывает карточку
- [ ] Сама игра исключена, соблюдён минимальный порог
- [ ] При малом объёме БД показывается меньше результатов, а не мусор
- [ ] Заполняется `method` (ADR-0009)

### Фаза 5 — Мониторинг и Force Run
- [ ] Дашборд показывает статус run, воркеров, счётчики, план дня
- [ ] SSE переподключается автоматически
- [ ] Подключение в середине run показывает историю, а не пустой экран
- [ ] `POST /api/runs` без токена → 401
- [ ] С неверным токеном → 403
- [ ] Сравнение токена constant-time (ADR-0007)
- [ ] Rate limit работает → 429
- [ ] Запуск при активном run → 409

### Фаза 6 — YouTube
- [ ] При выключенном флаге сервис работает без ключей YouTube
- [ ] Сбой YouTube не меняет статус игры
- [ ] `transcript_source` сохраняется и отображается
- [ ] При `metadata_only` явно указано, что расшифровки не было (ADR-0005)
- [ ] Исчерпание квоты отключает стадию мягко

### Фаза 7 — Сдача
- [ ] Сервис доступен по ссылке
- [ ] БД наполнена данными
- [ ] Raw AI logs сохранены по агентам, не редактировались (OQ-19)
- [ ] Merged `ai-conversation.jsonl` собран, содержит `timestamp`, `agent`, `role`,
      `event type` (OQ-20)
- [ ] В merged log включены только материалы этого проекта
- [ ] **Secret scan выполнен; при находке публикация остановлена и вопрос эскалирован**
- [ ] README описывает запуск, конфигурацию и ограничения без раскрытия секретов
- [ ] Сценарии восстановления проверены на живом стенде

## 6. Ручные проверки перед сдачей

- [ ] Пройти пользовательские сценарии U1–U7 из `DISCOVERY.md`
- [ ] Перезапустить сервис во время обработки — убедиться в корректном восстановлении
- [ ] Дважды нажать Force Run — убедиться в `409` на второй
- [ ] Просмотреть репозиторий на предмет секретов
- [ ] Сверить реализацию с каждым пунктом ТЗ

---

## 7. Правила эскалации

Немедленно остановиться и обратиться к Product/Tech Lead при:

- обнаружении секрета в raw AI logs (**не маскировать**, OQ-19);
- блокировке со стороны Metacritic (403);
- обнаружении, что требование ТЗ технически невыполнимо в согласованном виде;
- необходимости решения, меняющего согласованную архитектуру.

Молчаливое додумывание требований не допускается.
