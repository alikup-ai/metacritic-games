# Frontend

**Версия:** 1.0
**Дата:** 2026-09-09
**Статус:** реализовано (Phase 3B)
**Стек:** Next.js 15 (App Router), React 19, TypeScript 5.9

---

## 1. Архитектура

```
Браузер
   ↓  только свой origin
Next.js (web/)         ← серверные компоненты, API-клиент
   ↓  server-side, внутренняя сеть
HTTP API (src/api/)    ← контракт docs/API.md
   ↓
Application → Domain → PostgreSQL
```

Фронтенд — отдельный workspace в `web/` со своим `package.json`, `tsconfig.json` и
конфигурацией ESLint.

**Почему отдельный workspace.** Корневой `tsconfig.json` рассчитан на Node
(`"types": ["node"]`, `lib: ["ES2023"]` — без DOM). Добавление JSX и DOM в него
размыло бы изоляцию бэкенда: серверный код получил бы доступ к браузерным типам.
Две конфигурации проще одной универсальной.

### Структура

```
web/
├─ src/
│  ├─ app/                    маршруты (App Router)
│  │  ├─ layout.tsx           каркас, ссылка перехода к содержимому
│  │  ├─ page.tsx             каталог
│  │  ├─ loading.tsx          состояние загрузки каталога
│  │  ├─ error.tsx            непредвиденные ошибки
│  │  ├─ not-found.tsx        общая страница «не найдено»
│  │  └─ games/[id]/
│  │     ├─ page.tsx          карточка игры + разбор отзывов
│  │     └─ not-found.tsx     «игра не найдена»
│  ├─ components/             Score, GameCard, CatalogFilters, Pagination, AnalysisCard
│  └─ lib/
│     ├─ api/client.ts        единственное место обращений к API
│     ├─ api/types.ts         типы ответов
│     ├─ coverage.ts          формулировки полноты анализа
│     └─ safe-url.ts          проверка внешних ссылок
└─ e2e/                       Playwright + поддельный бэкенд
```

## 2. Обращение к API: same-origin вместо CORS

**Решение: `Браузер → Next.js → API`.** Браузер обращается только к origin Next.js;
запросы к бэкенду выполняются на сервере.

Почему так, а не прямые запросы из браузера:

1. **CORS не нужен вовсе.** Второго origin нет, поэтому нет и междоменных запросов.
   Это закрывает риск R-5 из Phase 3A без добавления заголовков и обработки OPTIONS.
2. **Адрес бэкенда не попадает в браузер.** `API_BASE_URL` — серверная переменная
   без префикса `NEXT_PUBLIC_`. Проверено: в клиентском пакете нет ни адреса,
   ни путей `/api/...`.
3. **Секреты остаются на сервере.** `ADMIN_TOKEN` и `LLM_API_KEY` браузеру
   недоступны в принципе — он не обращается к API напрямую.
4. **Бэкенд не изменялся.** Phase 3A осталась нетронутой.

Изоляция закреплена в коде: `src/lib/api/client.ts` начинается с `import 'server-only'`.
Случайный импорт клиента в клиентском компоненте станет ошибкой сборки, а не
незаметной утечкой.

## 3. Серверный и клиентский код

| Часть | Тип | Причина |
|---|---|---|
| Каталог (`page.tsx`) | Серверный компонент | Данные берутся на сервере, в браузер уходит готовая разметка |
| Карточка игры | Серверный компонент | То же; плюс скрытие адреса бэкенда |
| Разбор отзывов | Серверный компонент | Часть страницы игры |
| Панель фильтров | **Клиентский** (`'use client'`) | Нужны обработчики полей ввода |
| Обработчик ошибок | **Клиентский** | Требование Next.js |

Клиентских компонентов ровно два, и ни один не обращается к API: фильтры лишь
меняют адрес страницы, а данные снова запрашивает сервер.

**Состояние фильтров живёт в адресе страницы.** Ссылку можно сохранить в закладки
и отправить; кнопка «назад» работает ожидаемо. Локальное состояние компонента
этого не дало бы.

Опроса сервера из браузера (polling) нет.

## 4. Кеширование

Оценки и разбор отзывов обновляются после обхода источника и анализа, поэтому кеш
задаётся явно для каждого запроса, а не оставляется на умолчания.

| Запрос | `revalidate` | Обоснование |
|---|---|---|
| `GET /api/games` | 60 с | Каталог меняется после ежечасного обхода |
| `GET /api/games/:id` | 60 с | Та же частота обновления |
| `GET /api/games/:id/analysis` | 300 с | Анализ пересчитывается реже |
| `GET /api/platforms` | 3600 с | Набор платформ практически статичен |

Обе страницы с данными помечены сборкой как `ƒ (Dynamic)` — отрисовываются по
запросу. Статическая генерация здесь неуместна: она показывала бы оценки,
устаревшие на часы.

## 5. Раскрытие полноты анализа

Обязательная часть интерфейса, а не украшение.

Поля `analyzedCount`, `totalAvailable`, `coverage` и `snapshotCompleteness`
приходят из базы, где вычислены на этапе анализа. **Фронтенд их не пересчитывает
и собственной оценки качества не выводит** — только форматирует.

Пример: при `analyzedCount = 200`, `totalAvailable = 6595` показывается

> Проанализировано 200 из 6 595 отзывов (3,0%)

Дополнительно:

| Состояние | Что показывается |
|---|---|
| `coverage = 'sample'` | «Выводы основаны на выборке и не отражают мнение всех авторов» |
| `snapshotCompleteness = 'partial'` | «Получена только часть отзывов источника» |
| `snapshotCompleteness = 'incomplete'` | «Сбор отзывов был прерван» |
| Любое из перечисленного | Блок полноты выделяется предупреждающим оформлением |

`confidence` показывается **отдельно** от полноты: высокая уверенность на малой
выборке остаётся выводом по малой выборке.

### Ссылки на свидетельства

`evidenceRefs` сохраняются в разметке как `data-evidence-refs`, но не выводятся
пользователю текстом: `r1`, `r7` — внутренние номера отзывов внутри одного
анализа, они не соответствуют идентификаторам в `GET /api/games/:id/reviews` и
сами по себе пользователю ничего не говорят.

**GAP-3B-2 (открыт).** Чтобы показать свидетельства человекочитаемо, API должен
связывать `r1` с конкретным отзывом. Сейчас такой связи нет. Данные не выдумываются:
происхождение вывода сохранено в разметке, но как пользовательский текст не подаётся.

## 6. Отсутствующие данные

Ни одно отсутствующее значение не заменяется правдоподобной выдумкой.

| Ситуация | Поведение |
|---|---|
| Игра не найдена | Страница «не найдено» с ссылкой в каталог |
| Каталог пуст | «Каталог пока пуст — данные появятся после первого обхода» |
| Поиск ничего не дал | «Ничего не найдено» с предложением изменить условия |
| `analysis === null` | «Анализ пока не выполнен. Это не означает, что отзывов нет» |
| Есть только один из двух анализов | Второй блок честно сообщает об отсутствии |
| Оценки нет (`null`) | Прочерк «—», **не** ноль |
| Разработчик неизвестен | «Разработчик неизвестен»; издатель **не** подставляется |
| Платформ нет | «Сведения о платформах отсутствуют» |
| API недоступен | «Данные недоступны» без адреса бэкенда и текста ошибки |
| `similar: []` | Блок не показывается вовсе |

## 7. Безопасность

| Проверка | Как обеспечено |
|---|---|
| XSS через название, описание, тексты анализа | Весь текст выводится как содержимое JSX — React экранирует его сам |
| `dangerouslySetInnerHTML` | Не используется нигде |
| Опасные схемы ссылок | `safe-url.ts` разбирает адрес через `URL` и пропускает только `http`/`https`. `javascript:` отбрасывается — кнопка не отрисовывается |
| Внешние ссылки | `rel="noopener noreferrer"` при `target="_blank"` |
| Секреты в браузере | Клиентский пакет проверен: ноль вхождений `API_BASE_URL`, `ADMIN_TOKEN`, `LLM_API_KEY`, `DATABASE_URL`, путей `/api/...` |
| Переменные окружения | Ни одной с префиксом `NEXT_PUBLIC_` |
| Заголовки | `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`, `Referrer-Policy` |
| `X-Powered-By` | Отключён |

Тексты Metacritic и выводы модели считаются недоверенным содержимым: они
приходят из внешних источников и никогда не интерпретируются как разметка.

## 8. Доступность

- семантическая разметка: `header`, `main`, `nav`, `search`, `article`, `dl`, `table`;
- один `h1` на страницу, заголовки по иерархии;
- ссылка «Перейти к содержимому» — первая в порядке обхода;
- у всех полей ввода есть связанные `label`;
- фокус виден всегда (`:focus-visible`);
- оценки продублированы текстом для программ чтения с экрана: визуально «93»,
  озвучивается «Критики: 93 из 100»;
- у изображений осмысленный `alt`, у декоративных — `aria-hidden`;
- `prefers-reduced-motion` отключает анимацию;
- страница не прокручивается по горизонтали ни на одном размере (проверено тестом).

Тема следует системной (`prefers-color-scheme`).

## 9. Переменные окружения

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `API_BASE_URL` | `http://127.0.0.1:3001` | Адрес бэкенда. **Только серверная** |
| `API_TIMEOUT_MS` | `8000` | Тайм-аут запроса к API |

Переменных с префиксом `NEXT_PUBLIC_` нет намеренно: всё, что помечено этим
префиксом, попадает в браузер.

## 10. Локальная разработка

```bash
# 1. База данных
docker compose up -d postgres

# 2. Бэкенд (порт 3001)
npm install
cp .env.example .env      # заполнить DATABASE_URL
npm run migrate
npm run start:api

# 3. Фронтенд (порт 3000)
cd web
npm install
API_BASE_URL=http://127.0.0.1:3001 npm run dev
```

Проверки:

```bash
cd web
npm run typecheck
npm run lint
npm run build      # производственная сборка
npm run e2e        # E2E (поднимает поддельный бэкенд сам)
```

## 11. E2E-тесты

**Playwright**, два профиля: `desktop` (Chrome) и `mobile` (Pixel 7).

Выбор обоснован тем, что нужен настоящий браузер: проверяются переходы, работа
`select`, отсутствие горизонтальной прокрутки и то, что внедрённая разметка не
исполняется. Инструмент без браузера этого не покажет.

**Внешние сервисы не вызываются.** `e2e/mock-api.mjs` отвечает по контракту
`docs/API.md`; к Metacritic, OpenRouter и PostgreSQL обращений нет — их поведение
покрыто тестами Phase 1–3A.

Поддельный бэкенд намеренно содержит трудные случаи: игру без оценок, игру без
разработчика, выборку 200 из 6595, прерванный сбор, `javascript:` в ссылке на
видео и разметку в описании.

`reuseExistingServer: false` — иначе тесты шли бы против ранее поднятой,
устаревшей сборки (эта ошибка была допущена и исправлена при разработке).

## 12. Известные ограничения

| # | Ограничение | Причина |
|---|---|---|
| R-3B-1 | Страница «игра не найдена» отдаёт код 200 | Динамический маршрут начинает передаваться до проверки существования; Next не может изменить код после начала передачи. Страница помечается `noindex`, поэтому в поиск не попадает. Это документированное поведение Next, а не дефект реализации |
| R-3B-2 | `evidenceRefs` не показываются человекочитаемо | API не связывает ссылку с текстом отзыва — см. §5 |
| R-3B-3 | Фильтр по одной платформе | Ограничение API; для интерфейса достаточно |
| R-3B-4 | Похожие игры не показываются | Расчёт не реализован (решение OQ-3A-1) |
| R-3B-5 | Уязвимости PostCSS в зависимостях сборки Next | Транзитивные, срабатывают только на недоверенном CSS во время сборки; наш CSS написан в репозитории |
| R-3B-6 | Мониторинг и ручной запуск без интерфейса | Вне границ фазы |
