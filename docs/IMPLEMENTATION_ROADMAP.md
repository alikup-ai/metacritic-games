# План реализации — Metacritic Games Service

**Версия:** 1.0
**Дата:** 2026-09-07
**Статус:** все блокирующие вопросы закрыты; Фаза 0 и DATABASE DESIGN — в работе

---

## Принципы очерёдности

1. **Обязательная часть — раньше опциональной.** Полностью рабочая обязательная часть
   ценнее двух наполовину готовых опциональных.
2. **Мониторинг (доп. часть 2) — раньше YouTube (доп. часть 1).** Инверсия нумерации ТЗ
   сделана осознанно: мониторинг дешевле, надёжнее и заметнее проверяющему на единицу
   затраченного времени; YouTube несёт риск транскриптов и квот (ADR-0005).
3. **Каждая фаза завершается работоспособным состоянием** — сервис не бывает «сломан между
   фазами».
4. **Исследование опережает реализацию** там, где разметка не подтверждена (OQ-18).

## Фаза 0 — Каркас

**Цель:** воспроизводимое окружение и жёсткие границы с самого начала.

- Инициализация репозитория, TypeScript, ESLint, Prettier.
- Структура модулей (`ARCHITECTURE.md` §2).
- `dependency-cruiser` + правила границ слоёв в CI (ADR-0001).
- Docker Compose: app + PostgreSQL.
- Инструмент миграций, схема конфигурации с валидацией.
- CI: lint, types, границы, тесты, сборка образа.
- `/healthz`, `/readyz`.

**Готово, когда:** `docker compose up` поднимает сервис, CI зелёный, нарушение границ слоёв
роняет сборку.

## Фаза 1 — Ядро ingestion (сердце задания)

**Цель:** корректная, идемпотентная, восстанавливаемая обработка игр.

### 1.0 Исследование — ✅ ВЫПОЛНЕНО

- **OQ-18 закрыт.** Результат: `docs/METACRITIC_PLATFORM_SCORES.md`, решение — ADR-0008.
  Metascore достоверно привязан к платформе; Userscore публикуется только общий.
- Осталось: зафиксировать HTML-фикстуры (`elden-ring`, `the-witcher-3-wild-hunt`,
  `the-blood-of-dawnwalker` — отсутствующий developer).

### 1.1 Домен

- Сущности: `Game`, `GamePlatform`, `ProcessingDay`, `DailyClaim`, `Run`.
- Правила день-плана (ADR-0002), claim/lease (ADR-0004), идентичности (ADR-0003).
- Порты: `GameCatalogSource`, `GameRepository`, `ClaimRepository`, `RunRepository`.
- **Юнит-тесты без БД и сети.**

### 1.2 Инфраструктура

- Миграции: `game`, `game_platform`, `processing_day`, `daily_claim`, `run`, `run_event`.
- HTTP-клиент: timeout, retry с backoff+jitter, token bucket ≤1 req/s,
  обработка 403/429/5xx, circuit breaker.
- Парсеры: листинги, карточка игры (JSON-LD → fallback), developer из
  `data-testid="hero-summary-developer"`.
- Репозитории на PostgreSQL, advisory lock.

### 1.3 Оркестрация

- `PlanBatch`: фазы New Releases → See All, цикл добора до 20 **claimed**.
- `ClaimGames`: атомарный `INSERT ... ON CONFLICT DO NOTHING`.
- `ProcessGame`: стадии с раздельным сохранением.
- `ReapStaleClaims`: возврат просроченных lease.
- Ежечасный планировщик под advisory lock.

**Готово, когда:**
- За запуск обрабатывается 20 игр, начиная с New Releases.
- Повторный запуск в тот же день не берёт те же игры.
- Новый день начинает цикл заново.
- Существующая игра обновляется, не дублируется.
- Проходят все тесты корректности из `DEVELOPMENT_WORKFLOW.md` §5.
- Пересечение страниц листинга не приводит к пропускам (ADR-0002).

## Фаза 2 — Web UI

- REST: `/api/games` (пагинация, фильтр, поиск, сортировка), `/api/games/:slug`,
  `/api/platforms`.
- Страница списка: карточки с кратной информацией.
- Карточка игры: обложка, описание, developer (при `unknown` — «Разработчик не указан»),
  издатель отдельно, таблица оценок по платформам, трейлер.
- Фильтр по платформам, поиск по названию (debounce), сортировка по рейтингу.
- Состояние фильтров в URL. Индексы БД, включая trigram для поиска.
- Пустые состояния и состояния ошибок.

**Готово, когда:** проверяющий может найти игру, отфильтровать по платформе, отсортировать
по рейтингу и открыть карточку; p95 списка < 300 мс.

## Фаза 3 — Отзывы и LLM-резюме

- Парсер отзывов критиков и пользователей (**[ПРОВЕРЕНО]** — server-rendered).
- Хранение снимка отзывов + fingerprint.
- Порт `LlmProvider` + адаптер (OQ-6).
- Раздельные промпты для критиков и пользователей, структурированный вывод
  (`likes` / `dislikes` / `verdict`).
- **Fingerprint-gate:** не вызывать LLM, если отзывы не изменились.
- Обработка «отзывов нет» — без вызова LLM, явный статус.
- Логирование всех вызовов в `logs/ai/runtime/llm-calls.jsonl`.
- Отображение двух резюме в карточке, визуально различимых.

**Готово, когда:** в карточке видны отдельные резюме по критикам и пользователям; повторный
обход без изменений отзывов не тратит токены; отсутствие отзывов не ломает обработку.

## Фаза 4 — Похожие игры

- Алгоритм: жанры + платформы + developer/publisher + trigram названия, со взвешиванием.
- Исключение самой игры, минимальный порог схожести.
- Пересчёт при добавлении игр, кэш в `similar_game`.
- Блок в карточке с переходом по клику.

**Готово, когда:** в карточке отображаются релевантные похожие игры, клик открывает их
карточку; при малом объёме БД показывается меньше результатов, а не мусор.

**Здесь обязательная часть ТЗ выполнена полностью.**

## Фаза 5 — Мониторинг и Force Run (доп. часть 2)

- Шина событий: стадии → `run_event` → SSE (сохранение до рассылки).
- `GET /api/events` (SSE), `GET /api/status`.
- **`POST /api/runs` с аутентификацией** (решение по OQ-8) + rate limit;
  `202` при запуске, `409` если lock занят.
- Дашборд: статус run, состояния воркеров, счётчики, план дня (фаза, курсор), лента
  событий, последняя ошибка.
- Кнопка принудительного запуска с корректной обработкой «уже выполняется».

**Готово, когда:** проверяющий видит процесс обработки в реальном времени и может запустить
его вручную; неаутентифицированный запрос отклоняется.

## Фаза 6 — YouTube (доп. часть 1, за feature flag)

- Порт `VideoProvider` + адаптер YouTube Data API.
- Поиск летсплеев, выбор самого популярного по просмотрам.
- Каскад транскриптов: официальные субтитры → авто-субтитры → метаданные,
  с сохранением `transcript_source` (ADR-0005).
- LLM-заключение по тексту.
- Отображение в карточке: заключение, ссылка на ролик, **явная пометка источника**.
- Учёт квоты, кэширование, мягкое отключение при исчерпании.

**Готово, когда:** при включённом флаге в карточке появляется заключение со ссылкой; при
выключенном — сервис работает без ключей YouTube; сбой YouTube не влияет на статус игры.

## Критический путь и риски

```
Фаза 0 → Фаза 1 → Фаза 2 → Фаза 3 → Фаза 4 → [обязательная часть готова]
                                                  ↓
                                            Фаза 5 → Фаза 6 → Фаза 7
```

| Риск | Влияние | Митигация |
|---|---|---|
| Редизайн Metacritic | Высокое | JSON-LD как основной источник, golden-file тесты в CI |
| Блокировка по IP | Высокое | ≤1 req/s, честный UA, abort при 403, стабильный IP VPS |
| Нестабильность курсора страниц | Высокое | Реестр как источник истины (ADR-0002) — **уже решено** |
| Недоступность транскриптов | Среднее | Feature flag + деградация (ADR-0005) |
| Квота YouTube | Среднее | Кэш, счётчик, мягкое отключение |
| Стоимость LLM | Низкое | Fingerprint-gate, дешёвая модель |

**Точка невозврата:** после Фазы 4 обязательная часть выполнена. Если время ограничено,
Фазы 5–6 сокращаются без ущерба для основного требования.
